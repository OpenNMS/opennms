
= Notification Commands
:description: Default notification commands in {page-component-title} and how to create custom commands.

A notification command is a named, reusable execution profile for a Java class or external program command used to convey notices to targets.
{page-component-title} includes several default notification commands.
You can also create custom commands to send notifications to a platform of your choice.

== Default notification commands

[caption=]
.Default {page-component-title} notification commands
[cols="1,3"]
|===
| Command       | Description

| javaEmail
| Delivers a notice to the email address listed in the user's `email` contact field. +
Uses the in-process JavaMail notification strategy.

| javaPagerEmail
| Delivers a notice to the email address listed in the user's `pagerEmail` contact field.
By configuring `pagerEmail` to target an email-to-SMS gateway, you can easily configure SMS notifications. +
Uses the in-process JavaMail notification strategy.

| numericPage
| Sends a notice to a user's numeric pager. +
Implemented as an external command using the `qpage` utility.

| textPage
| Sends a notice to a user's alphanumeric pager. +
Implemented as an external command using the `qpage` utility.

|===

[[notification-strategies]]
== Notification strategies

A command with `binary="false"` names a Java class that implements the notification strategy interface in its `<execute>` element.
{page-component-title} includes the following strategies, all in the `org.opennms.netmgt.notifd` package:

[options="header"]
[cols="2,3"]
|===
| Class
| Description

| `JavaMailNotificationStrategy`
| Sends an email message.
See xref:operation:deep-dive/notifications/strategies/javamail.adoc[Email Notifications].

| `BrowserNotificationStrategy`
| Shows a desktop notification in the target user's web browser.
See xref:operation:deep-dive/notifications/strategies/browser.adoc[Browser Notifications].

| `WebhookNotificationStrategy`
| Sends an HTTP request with a templated body, for chat platforms and other webhook receivers.
See xref:operation:deep-dive/notifications/strategies/webhook.adoc[Webhook Notifications].

| `HttpNotificationStrategy`
| Posts form fields to a URL and can store part of the reply in the database.
See xref:operation:deep-dive/notifications/strategies/http.adoc[HTTP Form Notifications].

| `SnmpTrapNotificationStrategy`
| Sends an SNMPv1 or SNMPv2c trap.
See xref:operation:deep-dive/notifications/strategies/snmp-trap.adoc[SNMP Trap Notifications].

| `BSFNotificationStrategy`
| Runs a script through a JSR-223 script engine.
See xref:operation:deep-dive/notifications/strategies/scripting.adoc[Scripted Notifications].

| `TicketNotificationStrategy`
| Creates and closes trouble tickets for the alarm behind the notification.
See xref:operation:deep-dive/notifications/strategies/ticket.adoc[Trouble Ticket Notifications].

| `NullNotificationStrategy`
| Sends nothing and always reports success.
Use it to record a notice against a user, so that it appears in the user's notices and can be acknowledged in the web UI, without contacting anyone.
It takes no arguments.
|===

A command that uses the null strategy needs only a name and the class:

[source, xml]
----
<command binary="false">
  <name>nullNotify</name>
  <execute>org.opennms.netmgt.notifd.NullNotificationStrategy</execute>
  <comment>Record the notice without sending it</comment>
</command>
----

== Custom notification commands

You can edit `$\{OPENNMS_HOME}/etc/notificationCommands.xml` to customize and extend notification commands.

IMPORTANT: Use external binary notification commands sparingly, as they spawn additional process threads on your core {page-component-title} system.

=== Custom command configuration

The `streamed` attribute dictates whether the substitution text or switch text (or both) will be placed in the command line or in the input stream when the command starts to run.

.Place boilerplate arguments
[source, xml]
----
   <argument streamed="false">
      <substitution>-D</substitution>
   </argument>
----

.Place dynamic values
[source, xml]
----
   <argument streamed="false">
      <switch>-tm</switch>
   </argument>
----

When you combine the two (substitution and switch), each is written as a separate argument in the command line.
For example:

[source, xml]
----
   <argument streamed="false">
      <substitution>-Dnodeid=</substitution>
      <switch>-nodeid</switch>
   </argument>
Translates to:
   -Dnodeid= 8
and not:
   -Dnodeid=8
----
