
= Users

WARNING: This API is deprecated in {page-component-title} 37 and will be removed in {page-component-title} 38.
Use the xref:development:rest/users_v2.adoc[Users (v2)] API at `/api/v2/users` instead.

Users are stored in the database.
You cannot use hibernate criteria for filtering.
The write operations need the `ROLE_ADMIN` role, like the v2 API, and answer `403` without it.
They use the same checks as the v2 API:

* A new user ID must not be reserved or look like `admin` or `rtc`, and must not contain markup, whitespace, control characters or any of `: / \ % ? #`.
  The response is `400`.
* Duty schedules are validated (values that are already stored are accepted unchanged) and every role must be a known security role.
  The response is `400`.
* A user cannot be renamed with a form `PUT` that contains `username`.
  The response is `400`, which points to `PUT /api/v2/users/\{userId}/rename`.
* A form `PUT` key with an index or a nested path, such as `roles[0]`, is refused.
  The response is `400`.
* A `POST` without `user-id` is refused, and so is an unsalted password while the system property `org.opennms.users.allowUnsalted` is `false` (send `hashPassword=true`).
  The response is `400`.
* The `admin` and `rtc` users cannot be deleted, and `admin` keeps `ROLE_ADMIN`.
  The response is `400`.
* The last holder of `ROLE_ADMIN` cannot be deleted or lose the role, and a user who supervises an on-call role or is the target of a notification destination path cannot be deleted.
  The response is `409`.
* A save that races with another change, or is based on stale data, answers `409`.
* A caller without `ROLE_ADMIN` sees `xxxxxxxx` in place of the password hash of every user but their own.

`GET /users/whoami` is deprecated too.
Use `GET /rest/whoami`, which returns a different shape.

== GETs (reading data)

[caption=]
.Users API GET functions
[options="autowidth"]
|===
| Parameter | Description

| /users
| Get a list of users.

| /users/\{username}
| Get a specific user, by username.

| /users/whoami
| Get the authenticated user, without the password fields.
Use `GET /rest/whoami` instead.
|===

== POST (adding data)

POST requires XML using `application/xml` as its `Content-Type`.

[caption=]
.Users API POST function
[cols="1,3"]
|===
| Parameter | Description

| /users
| Add a user.
If supplying a password it is assumed to be hashed or encrypted already. +
To indicate that the supplied password uses the salted encryption algorithm rather than the older MD5-based algorithm, you need to pass an element named `passwordSalt` with text `true` after the password element. +
Note that you may add the query parameter `hashPassword=true` to tell OpenNMS you are passing an unencrypted password; it will hash and salt the password when it is saved.
|===

== PUTs (modifying data)

[caption=]
.Users API PUT functions
[cols="1,3"]
|===
| Parameter | Description

| /users/\{username}
| Update an existing user's `full-name`, `user-comments`, `password`, `passwordSalt`, and `duty-schedule` values. +
Note that, if you are setting the password, you may also add the query parameter `hashPassword=true` to tell OpenNMS you are passing an unencrypted password so it will hash and salt the password when it is saved.

| /users/\{username}/roles/\{rolename}
| Add a security role to the user.
|===

== DELETEs (removing data)

[caption=]
.Users API DELETE functions
[options="autowidth"]
|===

| /users/\{username}/roles/\{rolename}
