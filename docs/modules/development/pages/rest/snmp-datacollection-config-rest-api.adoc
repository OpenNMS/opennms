[[ga-snmp-datacollection-config-rest-api]]
= SNMP Data Collection Config REST API (v2)
:description: Manage SNMP data collection config (sources, profiles, MIB groups, resource types, system definitions) through the OpenNMS REST v2 API.

You can manage SNMP data collection over REST.
The same surface is used by the *Admin -> Manage SNMP Data Collection Config* page; the API is useful for automation, bulk imports, and version-controlled tooling.

The base path is `/api/v2/datacollectionconf`.

== Endpoint overview

All paths are relative to the base path.
For the request and response bodies, see the OpenAPI definition at `/api/v2/openapi.json`.

[options="header", cols="1,4,4"]
|===
| Method | Path | Description

3+h| Upload

| `POST`
| `/upload`
| Upload source XML files and `datacollection-config.xml`. See the Upload XML section.

3+h| Profiles

| `GET`
| `/profiles`
| List all profiles.

| `GET`
| `/profiles/\{profileId}`
| Get one profile.

| `POST`
| `/profiles`
| Create a profile.

| `PUT`
| `/profiles/\{profileId}`
| Update a profile.

| `DELETE`
| `/profiles`
| Delete profiles. The request body is a JSON array of profile IDs.

| `PUT`
| `/profiles/enable?enabled={true\|false}`
| Enable or disable profiles. The request body is a JSON array of profile IDs.

| `POST`
| `/profiles/\{profileId}/sources`
| Attach a source to a profile. The request body is the source name.

| `DELETE`
| `/profiles/\{profileId}/sources/\{sourceName}`
| Detach a source from a profile.

3+h| Sources

| `GET`
| `/filter/collectsources`
| List sources, with filter, sort and pagination parameters.

| `GET`
| `/collectsources/names-and-ids`
| List the name and ID of all sources.

| `GET`
| `/collectsources/\{collectionSourceId}`
| Get one source.

| `POST`
| `/collectsources`
| Create a source.

| `DELETE`
| `/collectsources?id=\{id}`
| Delete sources. Repeat `id` for more than one source.

| `PATCH`
| `/collectsources/status/\{enabled}?id=\{id}`
| Enable or disable sources.

| `GET`
| `/collectsources/\{collectionSourceId}/download`
| Download a source as a `datacollection-group` XML or JSON file.

| `GET`
| `/config/download`
| Download the top-level `datacollection-config` file.

3+h| MIB groups, resource types and system definitions

| `GET`
| `/filter/\{collectionSourceId}/{mibgroups\|resourcetypes\|systemdefs}`
| List the definitions of a source, with filter, sort and pagination parameters.

| `POST`
| `/collectsources/\{collectionSourceId}/{mibgroups\|resourcetypes\|systemdefs}`
| Add a definition to a source.

| `PUT`
| `/collectsources/\{collectionSourceId}/mibgroups/\{mibGroupId}`
| Update a MIB group. Resource types and system definitions use the same pattern.

| `DELETE`
| `/collectsources/\{snmpDataCollectionSourceId}/{mib-groups\|resource-types\|system-defs}?id=\{id}`
| Delete definitions from a source.

| `PATCH`
| `/collectsources/\{snmpDataCollectionSourceId}/{mib-groups\|resource-types\|system-defs}/status/\{enabled}?id=\{id}`
| Enable or disable definitions in a source.

3+h| Lookup by name

| `GET`
| `/{mibgroups\|resourcetypes\|systemdefs}/names`
| List the names of all definitions of this type. The resource type list also contains the instance values `0` and `ifIndex`.

| `GET`
| `/{mibgroups\|resourcetypes\|systemdefs}/names/\{name}`
| Get every definition with this exact name, with the source that defines it. See the Find a definition by name section.
|===

== Upload XML

Use this endpoint to import legacy `datacollection-config.xml` and `etc/datacollection/*.xml` files, or any externally version-controlled SNMP data collection definition.

Each `upload` part must be an XML file whose root element is either:

* `<datacollection-group>` — a source definition (registered as a new source on first upload, updated on subsequent uploads).
* `<datacollection-config>` — a profile-driver file with `<snmp-collection>` entries. At most one is allowed per request; its `<include-collection>` entries drive how new sources are attached.

How `profileNames` is applied depends on the batch composition:

[options="header"]
|===
| Batch composition | `profileNames` requirement

| All-new sources
| Required. New sources are attached to the named profiles.

| All-update sources (every source already exists in the DB)
| Optional. If non-empty, applied additively to every source.

| Mixed (≥1 new and ≥1 update)
| Required for the new sources; ignored for updates. Use `/profiles/\{profileId}/sources` to change existing memberships.

| `<datacollection-config>` present in the batch
| Ignored — the config's `<include-collection>` entries drive attachment.
|===

.Upload one or more source XML files and attach them to the `default` profile
[source, bash]
----
curl -u admin:admin \
  -X POST "http://localhost:8980/opennms/api/v2/datacollectionconf/upload" \
  -F "upload=@/opt/opennms/etc_archive/datacollection/cisco.xml;type=application/xml" \
  -F "upload=@/opt/opennms/etc_archive/datacollection/juniper.xml;type=application/xml" \
  -F "profileNames=default"
----

The response body contains per-file `success` and `errors` arrays so partial failures are visible without rolling back the whole batch.

[options="header"]
|===
| Status | Meaning

| `200 OK`
| Upload processed. Inspect the response body for per-file success/error details.

| `400 Bad Request`
| Invalid XML, missing required `profileNames` for an all-new source-only upload, or other request error.
|===

== Find a definition by name

A MIB group, resource type or system definition name can exist in more than one source.
Use these endpoints to find every source that defines a name.
The *Find by Name* tab of the admin page uses the same endpoints.

.Find every source that defines the `mib2-interfaces` MIB group
[source, bash]
----
curl -u admin:admin "http://localhost:8980/opennms/api/v2/datacollectionconf/mibgroups/names/mib2-interfaces"
----

The response is a JSON array with one entry for each source that defines the name.
Each entry contains the definition, its `enabled` flag, `collectionSourceId` and `collectionSourceName`.
A name that contains a slash, such as `Microsoft Windows NT/2000`, works as it is or encoded as `%2F`.

[options="header"]
|===
| Status | Meaning

| `200 OK`
| At least one source defines the name.

| `404 Not Found`
| No source defines the name.
|===
