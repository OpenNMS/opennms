= StrafePingMonitor
:description: Learn how to configure and use the StrafePingMonitor in OpenNMS {page-component-title} to use ICMP to monitor a specific endpoint and visualize packet loss.

This monitor uses ICMP to monitor http://en.wikipedia.org/wiki/Packet_delay_variation[packet delay variation] to a specific endpoint.
The main use case is to monitor a WAN endpoint and visualize packet loss and ICMP packet round-trip time deviation.
The StrafePingMonitor performs multiple ICMP echo requests (pings) and stores the response time of each as well as the packet loss.

This monitor is typically used on WAN connections and not activated for every ICMP-enabled device in your network.
Since StrafePingMonitor requires many more I/O requests than a single IcmpMonitor poll, use this monitor only where necessary to check packet loss.

Credit to Tobias Oetiker, as graphing of this feature is an adaptation of the http://oss.oetiker.ch/smokeping/[SmokePing] tool that he developed.

== Configuration and use

.Monitor-specific parameters for the StrafePingMonitor
[options="header"]
[cols="1,3,2"]
|===
| Parameter
| Description
| Default

3+|*Optional*

| rrd-repository
| Directory in which to store the response-time and packet-loss data.
Polling works without it, but it is needed for the latency and packet-loss graphs.
| n/a

| ping-count
| The number of pings to attempt each interval.
| 20

| failure-ping-count
| The number of pings that need to fail for the service to be considered down.
| 20

| wait-interval
| Time in milliseconds to wait between each ICMP echo-request packet.
| 50

| rrd-base-name
| The name of the RRD file to write (minus the extension, .rrd).
| Service name, in lowercase

| timeout
| Time in milliseconds to wait for each echo reply before counting the ping as lost.
| 800

| allow-fragmentation
| Whether outgoing packets may be fragmented.
Set to `false` to set the "Don't Fragment" bit.
| true

| dscp
| DSCP traffic-control value.
| 0

| packet-size
| Number of bytes of the ICMP packet to send.
| 64
|===

This monitor implements the <<reference:service-assurance/introduction.adoc#ref-service-assurance-monitors-common-parameters, Common Configuration Parameters>>.
It does not use the `retry` parameter: each ping is sent once, and lost pings count toward `failure-ping-count`.

== Examples

By default, you can find a separate poller package in `poller-configuration.xml` called `strafer`.
Configure the include-range or a filter to enable monitoring for devices with the service StrafePing.

The following example enables the monitoring for the StrafePing service on IP interfaces in the range `10.0.0.1` to `10.0.0.20`.
Additionally, you must assign the nodes to a node tag named `Latency`.

Example uses CentOS/RHEL path name.
For Debian/Ubuntu, use `/var/lib/opennms/rrd/response`.

Note that you must include the `monitor` section for each service in your definition.

The `filter`, `include-range`, `rrd`, and `downtime` elements are settings of the polling package, not monitor parameters.
They select the IP interfaces the package applies to, define the RRD step and archives, and set the polling interval during an outage.
See xref:operation:deep-dive/service-assurance/polling-packages.adoc[] and xref:operation:deep-dive/service-assurance/downtime-model.adoc[] for details.

[source, xml]
----
<package name="strafer" >
  <filter>categoryName == 'Latency'</filter> <1>
  <include-range begin="10.0.0.1" end="10.0.0.20"/> <2>
  <rrd step="300"> <3>
    <rra>RRA:AVERAGE:0.5:1:2016</rra>
    <rra>RRA:AVERAGE:0.5:12:1488</rra>
    <rra>RRA:AVERAGE:0.5:288:366</rra>
    <rra>RRA:MAX:0.5:288:366</rra>
    <rra>RRA:MIN:0.5:288:366</rra>
  </rrd>
  <service name="StrafePing" interval="300000" user-defined="false" status="on">
    <parameter key="timeout" value="3000"/> <4>
    <parameter key="ping-count" value="20"/> <5>
    <parameter key="failure-ping-count" value="20"/> <6>
    <parameter key="wait-interval" value="50"/> <7>
    <parameter key="rrd-repository" value="/opt/opennms/share/rrd/response"/> <8>
    <parameter key="rrd-base-name" value="strafeping"/> <9>
  </service>
  <downtime interval="30000" begin="0" end="300000"/> <10>
  <downtime interval="300000" begin="300000" end="43200000"/>
  <downtime interval="600000" begin="43200000" end="432000000"/>
  <downtime begin="432000000" delete="true"/>
</package>
<monitor service="StrafePing" class-name="org.opennms.netmgt.poller.monitors.StrafePingMonitor"/> <11>
----
<1> Package filter: only IP interfaces on nodes with the `Latency` tag are considered.
<2> Range of IP addresses to include, from beginning to end.
<3> RRD step and archives used for this package's response-time data.
<4> Time, in milliseconds, to wait for each echo reply.
<5> The number of pings to attempt each interval.
<6> The number of pings that need to fail for the service to be considered down.
<7> Time, in milliseconds, to wait between each ICMP echo-request packet.
<8> Base directory of an RRD repository in which to store this service monitor's response-time samples.
<9> The file name of the RRD file.
<10> Downtime model: how often to poll the service while it is down.
With `delete="true"`, the service is deleted from a managed interface once it has been down for longer than `begin`.
<11> Required *monitor* section.
