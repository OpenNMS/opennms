[[ref-performance-data-collectors]]
= Collectors
:description: Overview of official documentation for collectors in OpenNMS {page-component-title}.

This section describes all available built-in xref:operation:deep-dive/performance-data-collection/introduction.adoc[performance data collectors].
You can configure them to allow complex monitoring to meet the needs of your environment.
You can use xref:operation:deep-dive/meta-data.adoc#ga-meta-data-dsl[Metadata-DSL] to dynamically interpolate metadata into parameter values during the collection process.

For information on how to extend the functionality of these monitors, see the xref:development:development.adoc#development[Development section] to contribute to the project.

[[ref-performance-data-collectors-common-parameters]]
== Common configuration parameters

Collectd handles the following service parameters for every collector, in addition to the collector-specific parameters described on each collector's page.
Set them as `<parameter>` elements of a service in a xref:operation:deep-dive/performance-data-collection/collectd/collection-packages.adoc#ga-collectd-packages-services[collector package].

.Optional common configuration parameters
[options="header"]
[cols="1,3,2"]
|===
| Parameter
| Description
| Default

| thresholding-enabled
| Whether collected performance data should be tested against thresholds.
Set it to `false` to skip threshold evaluation for the service.
| true

| ttl
| Time to live, in milliseconds, of the requests sent to a Minion for the collection.
For the SnmpCollector, it applies to the SNMP requests sent to the node's location.
| The service's collection interval
|===

[[ref-performance-data-collectors-minion-parameters]]
=== Minion configuration parameters

When a node is assigned to a non-default location, collectors that support Minions run the collection on a Minion at that location.
If a location has multiple Minions, the collection may run on any of the Minions that are currently available.
Use the following parameters to override this behavior and control where the collection runs.

.Optional Minion configuration parameters
[options="header"]
[cols="1,3,2"]
|===
| Parameter
| Description
| Default

| location
| Specify the location at which to run the collection.
| The location of the associated node.

| system-id
| Specify the system ID of the Minion on which to run the collection.
| n/a

| use-foreign-id-as-system-id
| Use the foreign ID of the associated node as the system ID.
| false
|===

NOTE: When you specify a system ID, also set the location to the corresponding location for that system.

These parameters do not apply to the SnmpCollector.
It always runs on {page-component-title} and sends its SNMP requests through the location of the node.
