.Create a project directory for {page-component-title} Minion and create a `docker-compose.yml` file.
[source, console]
----
mkdir minion
cd minion
vi docker-compose.yml
----

[source, docker-compose.yml]
[subs="verbatim,attributes"]
----
---
version: '3'

services:
  minion:
ifeval::["{page-component-title}" == "Horizon"]
    image: opennms/minion:{full-display-version}
endif::[]
ifeval::["{page-component-title}" == "Meridian"]
    image: opennms/meridian-minion:{full-display-version}
endif::[]
    container_name: minion<1>
    environment:
      TZ: 'America/New_York'<2>
      JAVA_MIN_MEM: 512M<3>
      JAVA_MAX_MEM: 2048M<4>
      OPENNMS_BROKER_URL: 'failover:tcp://core-instance-ip:61616'<5>
      MINION_LOCATION: 'my-location'<6>
      MINION_ID: 'my-minion'<7>
    command: ["-f"]
    #volumes:
    #  - ./keystore/scv.jce:/opt/minion/etc/scv.jce<8>
    healthcheck:
      test: "/health.sh"<9>
      interval: 30s
      timeout: 6s
      retries: 3
    ports:<10>
      - '514:1514/udp'
      - '162:1162/udp'
      - '8201:8201/tcp'
----
<1> Friendly container name
<2> Set the time zone. To list all available time zones, use `timedatectl list-timezones`.
<3> Optional. Use to control the minimal Java heap size.
<4> Optional. Use to control the maximum Java heap size.
<5> Replace the broker endpoint URL that goes to your {page-component-title} Core instance. If you have ActiveMQ with SSL running, replace `tcp` with `ssl`.
<6> Replace `my-location` with a location name that represents the remote location where the Minion is running.
<7> Set a unique human-readable Minion identifier. If not set, every Minion gets the same placeholder ID, so always set a unique one.
<8> Keystore file with encrypted credentials for authenticating broker endpoints.
Initially these lines should be commented out, and will need to be activated after the file has been created on the local system.
<9> Run our health check to indicate the Minion is ready. It uses the `opennms:health-check` internally running in Karaf.
<10> Publish ports for Syslog, SNMP trap listener, and the SSH access to the xref:reference:karaf-shell/karaf-shell.adoc[Karaf shell].

The Minion process in the container runs as a non-root user and can't open privileged ports < 1024.
The Syslog and SNMP trap listeners in the container listen on 1514/udp and 1162/udp by default.
We publish them on the privileged ports (514/udp, 162/udp) and do not have to give additional permissions to the Minion process in the container.

CAUTION: Some environments do not allow the use of ICMP (ping) for non-root users.
         {page-component-title} Minion runs as a non-privileged user in the container with `userid=10001, groupid=10001`.
         You can verify with `sysctl -n net.ipv4.ping_group_range` if the group id `10001` is in the allowed group range.
         If not, add the following lines in your service definition in the `docker-compose.yml` file.

[source, docker-compose.yml]
----
sysctls:
  net.ipv4.ping_group_range: "10001 10001"
----

TIP: To run with Apache Kafka or configure flow listeners, see the xref:reference:configuration/minion-docker.adoc#minion-docker[Minion configuration reference].

Next, we need to create the keystore file and add the credentials for connecting to the core {page-component-title} server.

.Initialize the keystore with credentials
[source, console]
----
mkdir keystore
chown -R 10001:10001 keystore<1>
docker compose run --rm -v $(pwd)/keystore:/keystore minion -s<2>
----
<1> Assign ownership so the container user account can write within the directory.
<2> When prompted, enter the username and password for a `ROLE_MINION` user account on the {page-component-title} server.
You may be prompted for the same username and password twice.

.Edit the `docker-compose.yml` file to uncomment the keystore file
[source, diff]
----
-    #volumes:
-    #  - ./keystore/scv.jce:/opt/minion/etc/scv.jce
+    volumes:
+      - ./keystore/scv.jce:/opt/minion/etc/scv.jce
----

.Validate your Docker Compose file
[source, console]
----
docker compose config -q
----

.Start the service in background
[source, console]
----
docker compose up -d
----

.Verify the connectivity and the configuration with the health check
[source, console]
----
docker compose exec minion bin/client opennms:health-check
----

.The endpoints should be reachable and the bundles should be installed successful
[source, output]
----
Verifying installed bundles      [ Success  ]
Connecting to JMS Broker         [ Success  ]
=> Everything is awesome
----
