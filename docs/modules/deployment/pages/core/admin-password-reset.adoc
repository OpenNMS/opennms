
[[reset-admin-password]]
= Reset the Web UI Admin Password
:description: Learn how to reset your OpenNMS Admin password on the command line.

This section explains how to set the web UI admin password using the {page-component-title} installation script.

After you install {page-component-title}, the web UI admin user's password is set to `admin` by default.
As long as this password remains unchanged, you will be prompted to change this password every time you sign in to the {page-component-title} web UI.

You can also change the password by using the *Change Password* option in the UI any time you are logged in.
In the case of a forgotten password or deployment scenarios that require users to set this password on installation, you can use the {page-component-title} installation script to reset this password.

You need to add the option ` -R` (or `--reset-webui-password`) and provide the password to set as an argument.

.This example skips the upgrade tasks and sets the web UI admin password to "foobar":
[source, shell]
sudo /opt/opennms/bin/install -S -R foobar

On a new installation or an upgrade, the admin user may not exist in the database yet.
In that case `-R` takes effect after the upgrade tasks of the same run, so do not use `-S` together with `-R` then.
If you use `-S` and the admin user does not exist, the installer does not set the password: run `-R` again after the upgrade.
If the password cannot be set after the upgrade tasks for any other reason, the upgrade fails: the installer ends with "UPGRADE FAILED", and {page-component-title} does not start until the installer has run again without the failure.
If the admin user does not exist yet and {page-component-title} is running, `install -R` fails the upgrade: setting the password after the upgrade tasks is a critical task that needs {page-component-title} to be stopped.
Stop {page-component-title} first, then run `install -R`.
An install whose users are set up already, but that has no admin user (for example, because it was deleted or renamed), does not wait for the upgrade tasks: the installer reports that the password was not set, and nothing fails.
If an earlier upgrade task fails so that the admin user is not created (for example, the copy of `users.xml` into the database), the password is not set either and the upgrade fails: fix the cause and run the installer again with `-R`.

The password must not be blank.
The users are stored in the database, so `-R` needs the database schema of this version: when you upgrade from an older version, use `-R` together with `-d` (for example, `install -dis -R foobar`).
